# API CONTRACT

Shared source of truth so four people can build in parallel. Base path: `/api/v1`. Swagger is generated by FastAPI at `/docs`, this file is the agreed design.

Auth: none in Sprint 1. From Sprint 2 every endpoint except room/slot listing needs `Authorization: Bearer <jwt>`.

The browser client (`front/`) calls the relative path `/api/v1/...` on its own origin: Nginx (Docker) and the Vite dev server proxy `/api` to the API, so no CORS configuration is needed. The front maps the error `code` (e.g. `SLOT_TAKEN`, `TOO_LATE_TO_CANCEL`) to a Spanish message.

## Error format (BR-X1)

```json
{ "detail": "Time slot is already booked", "code": "SLOT_TAKEN" }
```

Codes: `NOT_FOUND`, `SLOT_NOT_FOUND`, `USER_NOT_FOUND`, `VALIDATION_ERROR`, `DUPLICATE`, `SLOT_TAKEN`, `SLOT_NOT_AVAILABLE`, `SLOT_OVERLAP`, `ROOM_INACTIVE`, `USER_INACTIVE`, `INVALID_PLAYERS`, `TOO_LATE_TO_CANCEL`, `TOO_LATE_TO_MODIFY`, `INVALID_TRANSITION`, `UNAUTHORIZED` (401, missing or invalid token), `FORBIDDEN`, `INTERNAL_ERROR` (unexpected 500, message is always "Internal server error").

## Rooms (E2)

| Method | Path | Sprint | Description | Success |
|--------|------|:------:|-------------|---------|
| POST | `/rooms` | 1 | Create room (catalog fields required; `slug` generated from name if omitted) | 201 |
| GET | `/rooms` | 1 | List rooms (`?status=active`) | 200 |
| GET | `/rooms/{id or slug}` | 1 | Get room by numeric ID or URL slug | 200 |
| PUT | `/rooms/{id}` | 1 | Partial update (only sent fields). `slug` is immutable; `null` or unknown fields → 422 | 200 |
| PUT | `/rooms/{id}/deactivate` | 1 | Deactivate | 200 |
| PUT | `/rooms/{id}/activate` | 1 | Activate (idempotent) | 200 |

Room catalog fields (ticket 056): `slug` (unique, lowercase letters/digits/hyphens, at least one letter, immutable once created, generated from `name` when omitted; a digits-only name gets a `sala-` prefix, e.g. `sala-1923`), `genre`, `min_players`, `difficulty` (1 to 5), `hook`, `story`, `audience`.

`PUT /rooms/{id}` acts as a true partial update (`exclude_unset`): fields the client does not send keep their stored value. Because every column is NOT NULL, an explicit `null` returns 422; unknown fields (including `slug`) are rejected with 422 to keep friendly URLs (`/salas/:slug`) stable.

## Time slots (E2)

| Method | Path | Sprint | Description | Success |
|--------|------|:------:|-------------|---------|
| POST | `/time-slots` | 1 | Create slot (`room_id`, `starts_at`, `ends_at`) | 201 |
| GET | `/time-slots` | 1 | List (`?room_id=&date=&available=true`) | 200 |
| GET | `/time-slots/{id}` | 1 | Get slot, includes computed `is_bookable` | 200 |
| PUT | `/time-slots/{id}` | 1 | Update times / status | 200 |
| DELETE | `/time-slots/{id}` | 1 | Delete (BR-S6) | 204 |
| POST | `/rooms/{id}/time-slots/generate` | 2 | Bulk generate available slots (admin) | 200 |

`POST /rooms/{id}/time-slots/generate` is admin-only: 401 `UNAUTHORIZED` without a valid token, 403 `FORBIDDEN` for clients/staff. Body: `date_from`, `date_to` (inclusive UTC days, at most 90 days apart, BR-S8), `first_start`, `last_start`. It creates `available` slots per day spaced by `room.duration + 30 min` (BR-S7), skipping slots in the past (BR-S2) and overlaps (BR-S3). Returns `{"created_count": n, "skipped_count": m}`. An unknown room is 404 `NOT_FOUND`, an inactive room is 409 `ROOM_INACTIVE` (BR-R4), and an invalid date/time range is 422 `VALIDATION_ERROR`.

## Bookings (E3)

| Method | Path | Sprint | Description | Success |
|--------|------|:------:|-------------|---------|
| POST | `/bookings` | 1 | Create (`user_id`, `time_slot_id`, `players`) | 201 |
| GET | `/bookings` | 1 | List with room, slot, user, can_modify (`?user_id=&status=&date_from=&date_to=`) | 200 |
| GET | `/bookings/{id}` | 1 | Get booking with room, slot, user, can_modify | 200 |
| PUT | `/bookings/{id}` | 1 | Change `players` and/or `time_slot_id` (BR-B7, BR-L5) | 200 |
| PUT | `/bookings/{id}/confirm` | 1 | PENDING -> CONFIRMED | 200 |
| PUT | `/bookings/{id}/cancel` | 1 | Cancel (BR-B6) | 200 |
| GET | `/bookings/today` | 2 | Today's bookings (staff, admin), ordered by slot start, cancelled excluded | 200 |
| PUT | `/bookings/{id}/start` | 2 | CONFIRMED -> IN_PROGRESS (staff, admin; only on the day of the slot, UTC: BR-G3) | 200 |
| PUT | `/bookings/{id}/finish` | 2 | IN_PROGRESS -> COMPLETED (staff, admin) | 200 |
| POST | `/bookings/{id}/result` | 2 | Register result (`completed`, `completion_time` in seconds ≥ 0; staff, admin). Only once, only when `COMPLETED`: otherwise 409 `INVALID_TRANSITION` / `DUPLICATE` | 201 |
| GET | `/bookings/export.csv` | 2 | CSV export (admin) | 200 |

The staff/admin endpoints above answer 401 `UNAUTHORIZED` without a valid token and 403 `FORBIDDEN` for a client.

`GET /bookings` and `GET /bookings/{id}` return a `BookingDetail`: the booking fields plus `time_slot` (id, starts_at, ends_at, status), `room` (id, name, `slug` as stored in the room, capacity, base_price), `user` (`name`), `result` (`null` until a result is registered, then `completed` + `completion_time`) and `can_modify` (status `PENDING`/`CONFIRMED` and slot 24h or more away: same rule as modify and cancel, BR-B6/BR-B7).

`date_from` / `date_to` filter on `time_slot.starts_at` as inclusive UTC days. `date_from` after `date_to` returns 422 `VALIDATION_ERROR`. Tabs: Upcoming = `date_from=today`, Past = `date_to=yesterday`, Cancelled = `status=CANCELLED`.

## Pagination (Sprint 2)

`GET` lists accept `?page=1&size=20` and return:

```json
{ "items": [], "total": 0, "page": 1, "size": 20 }
```

In Sprint 1 lists return a plain array.
