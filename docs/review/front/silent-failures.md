## Confirmed OK (checked, no silent failure)

- **admin-users**: loading, error, empty and mutation-error states; `useUpdateUser` invalidates on `onSettled`; `userErrorMessage` falls back through the common error map.
- **staff**: `StaffPlanningPage` handles pending, error, empty; `GameActions` and `ResultForm` show mapped mutation errors; the `completion_time` schema guards the `''` to 0 coercion.
- **my-bookings**: `MyBookingsPage` and `GameHistoryPage` handle loading, error, empty; cancel/modify/change-slot dialogs show mutation errors, reset on close, invalidate on success; backend scopes `GET /bookings` to the user.
- **profile**: `ProfilePage`, `ScoreBoard`, `ProfileForm` show error and success; `computePlayerStats` guards the empty list.
- **rooms**: `RoomsPage` and `RoomsCorridor` have loading/error/empty; `RoomPage` separates 404 from other errors.
- **auth**: `RequireRole` handles a failed role lookup with retry and logout and does not flash a 403; Login/Register show Supabase errors; the Axios 401 interceptor routes to the unauthorized handler.
- **Other**: `SlotForm` and `AdminSlotsPage` show action and load errors (except SF-9); `useWebGLSupport` uses a fallback.
- **Tests**: no `skip`, `todo`, `expect(true)` or assertions inside `try/catch` outside the SF-14 file; the only `catch {}` is a harmless JSDOM shim in `adminRooms.test.jsx:22`.

**Not checked**: Three.js scene internals, per-feature i18n files other than `adminRooms`, every test file individually.
