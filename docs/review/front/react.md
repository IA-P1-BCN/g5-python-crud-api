## Confirmed OK

- **Hooks**: no conditional hooks; custom hooks use the `use` prefix; `useMediaQuery` uses `useSyncExternalStore`; `Corridor.jsx` has cleanup (`dispose`, AbortController, WebGL-failure fallback); `AuthProvider` subscription is unsubscribed with an `active` flag.
- **State placement** matches `ARCHI.md` (TanStack Query / Zustand / Context / URL); mutations invalidate the right keys in my-bookings, staff and admin-users; `RoomsCorridor` keeps the scene from rebuilding on refetch.
- **Forms**: login, register, checkout, profile and staff result use RHF + Zod with `noValidate`; `resultSchema` handles the empty-number case; `Field` has label/`htmlFor`, `aria-invalid`, `aria-describedby`, `role="alert"`.
- **Route guards**: `RequireAuth` waits for session restore; `RequireRole` handles loading, unauthenticated, role-lookup error (retry and logout) and 403; `hasRole` fails closed. Only admin-rooms lacks a guard (R-4).
- **Errors**: `mapApiError` + per-feature tables used in my-bookings, staff, admin-users, admin-slots; `RoomPage` separates 404 from other errors; loading/error/empty states in rooms, my-bookings, history, staff, admin-users.
- **HTTP**: one Axios instance, token interceptor, one 401 handler, no bare `fetch`.
- **Front security**: no `dangerouslySetInnerHTML`, no `localStorage` use (Supabase manages the session), no `target="_blank"`, only public Supabase URL and publishable key in `VITE_*`.
- **Performance**: `staleTime` on `useRoom`/`useRooms`; `keepPreviousData` in admin users; stable `key={id}`, no `key={index}`.
- **Accessibility**: `Button` native with `aria-busy`, `Chip` `aria-pressed`, `Pagination` `aria-disabled`, `Spinner`/`Skeleton` respect reduced motion, `Alert`/`Toast` roles, dialogs on Radix.
- **Tests**: shared MSW setup uses `onUnhandledRequest: 'error'`; most tests query by role/label with `userEvent`; success, error and empty paths covered for rooms, booking, admin-slots; auth tests mock Supabase and exercise real guards.
